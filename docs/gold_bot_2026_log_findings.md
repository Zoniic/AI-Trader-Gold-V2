## 2. ⭐ มีสองเอนจิน — และเอนจินที่สเปกให้ความสำคัญ แทบไม่ได้ใช้งานจริง

จัดกลุ่มตาม flag ทั้ง 3 ตัว (trailing / careful / snowball) ได้ผลสะอาดมาก:

| trailing | careful | snowball | จำนวนไม้ | มี TP | ตีความ |
|---|---|---|---|---|---|
| False | False | False | **9** | **9/9** | **Engine A** — ไม้จากสัญญาณ M30 มี TP ไม่ trail |
| True | True | True | **202** | 3 | **Engine B** — runner ไล่ trailing lot ฐาน |
| True | False | True | **20** | 2 | **Engine B** — lot ทบ |
| True | True | False | 2 | 2 | (เคสหายาก) |

→ **95% ของไม้ทั้งหมดคือ Engine B** (trailing runner ไม่มี TP)
→ Engine A ที่สเปกอธิบายละเอียด (ribbon → เปิด 2 ไม้ `_0`/`_1`) **มีแค่ 9 ไม้ใน 5 สัปดาห์**

**ผลต่อการออกแบบ: ระบบนี้คือ trailing-runner engine เป็นหลัก ไม่ใช่ signal engine**

## 3. ⭐ TP — ปิดคดีได้แล้ว

ไม้ที่ตั้ง TP ไว้จริงมีแค่ **16 ไม้จาก 233 (6.9%)** ในนั้นปิดแล้ว 13 ไม้:

| ผลลัพธ์ | จำนวน | รายละเอียด |
|---|---|---|
| ปิด "เลย" TP ไปนิดเดียว | **4** | +0.44, +0.03, +0.37, +0.05 จุด |
| **ปิดก่อนถึง TP** | **9** | ห่าง TP ถึง −25 ถึง −57 จุด |
| ปิดตรง TP เป๊ะ | 0 | — |

**แก้ข้อสรุปเดิม:** สเปกบอก "TP ไม่เคยทำงาน ราคาปิดเลย TP เสมอ" — จริงแค่ครึ่งเดียว
ความจริงคือ **ไม้ส่วนใหญ่ (9/13) ออกก่อนถึง TP ด้วย stop/trailing** ส่วน 4 ไม้ที่ "เลย TP"
คือ TP โดนจริงแล้วมี slippage เล็กน้อย

→ **TP แทบไม่มีบทบาทในระบบนี้** (6.9% ของไม้ และในนั้นถึงเป้าแค่ 31%)
→ ยืนยัน **Option A (ไม่มี TP ใช้ trailing ล้วน)** คือสิ่งที่บอทจริงทำ ไม่ใช่ Option B

## 4. ⭐ `careful` — v3 ถูก, v2 ผิด

> 🔧 **แก้ไขการวิเคราะห์ (สำคัญ):** ฉบับแรกของเอกสารนี้สรุปว่า v3 แม่นแค่ 16.1% ซึ่ง **ผิด**
> สาเหตุ: มี 7 ไม้ที่เปิดใน log แต่ไม่เคยปิด (ยังค้างตอน log จบ) ทำให้ counter "ไม้ที่ถืออยู่"
> ค้างค่าตลอดกาล ทุกไม้เลยดูเหมือน "มีของอยู่" หมด — แก้โดยนับแบบ interval overlap
> (ไม้ j ถืออยู่ตอนเปิดไม้ i ก็ต่อเมื่อ `open_j < open_i < close_j` และรู้ทั้งสองจุดจริง)

ทดสอบกับ 248 ไม้ที่มีข้อมูลครบ:

| สมมติฐาน | ความแม่น |
|---|---|
| v2: anti-martingale (ชนะ → False → ทบ) | 62.1% |
| **v3: ไม้แรก=True / ไม้เติม=False** | **78.6%** ✅ |

**ความสัมพันธ์เป็นเส้นตรงชัดเจน — ยิ่งถือไม้เยอะ ยิ่งไม่ careful:**

| ไม้ที่ถืออยู่ตอนเปิด | careful=True | จำนวน |
|---|---|---|
| **0 (ไม้แรก)** | **94.8%** | 173 |
| 1 | 66.0% | 47 |
| 2 | 55.6% | 18 |
| 3 | 30.0% | 10 |

→ **ยืนยันครึ่งแรกของ v3 หนักแน่นมาก: เปิดไม้แรกตอนพอร์ตว่าง = careful True 94.8%**
→ ครึ่งหลัง (ไม้เติม = False) เป็น**แนวโน้ม ไม่ใช่กฎตายตัว** (ไม้เติม careful=False แค่ 41.3%
   แต่สัดส่วนเพิ่มขึ้นเรื่อยๆ ตามจำนวนไม้ที่ถือ)

**ส่วน v2 หักล้างชัด:** หลัง**ชนะ** careful ยังเป็น True ถึง 74.1% (ถ้าเป็น anti-martingale ต้องเป็น False)

**careful ผูกกับขนาด lot แน่นมาก:**

| lot | careful=True |
|---|---|
| 0.04 (ฐาน) | 88.2% |
| 0.07 (ฐาน) | 92.6% |
| 0.08 | 62.5% |
| 0.14 (ทบ) | 14.3% |
| 0.16 (ทบ) | **0%** |

ทดสอบตรงๆ: `lot = 2× ไม้ก่อนหน้า` ⟺ `careful=False` — **ตรง 87.0%**
(ไม้ที่ lot เป็น 2 เท่าของไม้ก่อน มี 10 ไม้ เป็น careful=False ถึง 9 ไม้ = 90%)

### สรุปกฎที่ใช้ implement ได้

```
เปิดไม้ตอนพอร์ตว่าง        -> careful=True,  lot = base
เติมไม้ขณะมีของอยู่แล้ว    -> careful=False, lot = 2 × base  (แนวโน้ม ยิ่งถือเยอะยิ่งชัด)
```

⚠️ นี่คือ **pyramiding ที่เติมหนักขึ้น** ไม่ใช่ anti-martingale ตามผลแพ้ชนะ
— ตรงกับที่ v3 ระบุไว้ และเป็นต้นเหตุของ DD หนัก (19/6 เติม short สามชั้น 0.14 ทุกชั้นระหว่างราคาไหลลง)

## 5. SL — หลักฐาน "swing structure" อ่อนกว่าที่สเปกอ้าง

สเปกอ้างว่า SL ซ้ำกันข้ามไม้ = ระดับโครงสร้าง ตรวจจริง:

- ค่า SL ที่ไม่ซ้ำเลย: **195 ค่า**
- ค่า SL ที่ซ้ำ ≥ 2 ครั้ง: 27 ค่า (54 ไม้)
- **แต่ในนั้นส่วนใหญ่คือคู่ `_0`/`_1` ที่เปิดจากสัญญาณเดียวกัน entry เดียวกัน** — ไม่ใช่ไม้คนละจังหวะที่ใช้ระดับเดียวกัน
- เหลือเคสที่ entry ต่างกันจริงแต่ SL เดียวกัน: **แค่ 2 เคส**

ระยะ SL: min 2.46 / p25 16.83 / median 19.54 / p75 21.81 / max 36.25

→ กระจุกตัวแน่นรอบ 17–22 จุด (IQR แคบมาก) ซึ่ง**เข้ากับ ATR multiple มากกว่า swing structure**
(swing จริงจะกระจายกว้างกว่านี้มาก) — ยกเว้นหางล่างที่ 2.46 กับหางบน 36.25
→ **ยังสรุปไม่ได้ 100%** ต้องเอาข้อมูลราคา M30 จริงมาทาบถึงจะชี้ขาด (Test B ใน Phase 1 ของสเปก)

## 6. สัญญาณ (Signals line)

- `signal3 = 0` ทั้ง 61 บรรทัด → **ฟิลเตอร์ตัวที่ 3 ไม่เคยถูกใช้จริง** (ยืนยันตามสเปก)
- `signal1 == signal2` ทุกบรรทัด → เป็นตัวเดียวกันหรือถูก gate ให้ต้องตรงกัน
- `To open=True` เมื่อ signal=0: **24/24 (100%)**
- `To open=True` เมื่อ signal≠0: **16/37 (43%)**

→ ยืนยันกฎ **state-change** สำหรับ Engine A (สัญญาณค้างค่าเดิม = ไม่เปิด)
→ และยืนยันว่า **signal=0 คือใบอนุญาตให้ Engine B ทำงานเสมอ**

## 8. สรุปสิ่งที่ต้องเปลี่ยนในการออกแบบ MIDAS

| หัวข้อ | ที่เคยเข้าใจ | ความจริงจาก log | ผลต่อ MIDAS |
|---|---|---|---|
| แกนหลักของระบบ | signal engine M30 (ribbon) | **trailing runner 95%** | MIDAS ทำ signal engine เป็นหลัก = ผิดแกน |
| TP | Option B (partial TP) | **TP แทบไม่ถูกใช้ (6.9%)** | ควรใช้ Option A ไม่มี TP |
| careful | anti-martingale (v2) / position state (v3) | **v3 ถูก (78.6%) — ไม้แรก=True, ไม้เติม=ทบ lot** | implement ได้ = pyramiding |
| SL | swing structure | **น่าจะ ATR multiple มากกว่า** | MIDAS ใช้ swing = อาจผิด |
| ผลงานจริง | MAR 3.1 / +900% | **PF 1.06, 7 ไม้อุ้มทั้งระบบ** | ตั้งความคาดหวังใหม่ |

**ข้อเสนอลำดับถัดไป (เรียงตามผลกระทบ):**
1. ทดลอง MIDAS แบบ **ไม่มี TP เลย + trailing ล้วน** (Option A) — ตรงกับบอทจริงที่สุด
2. เปลี่ยน SL จาก swing เป็น **ATR multiple ~1.5–2×** ให้ตรงกับการกระจายจริง (median 19.5 จุด)
3. **pyramiding มีจริงและกฎชัดแล้ว** (ไม้แรก base / ไม้เติมทบ 2 เท่า) — แต่ backtest/live ของ
   โปรเจกต์นี้เป็นสถาปัตยกรรม "ทีมละ 1 ไม้พร้อมกัน" จึง implement ไม่ได้โดยไม่รื้อ engine
   → ถ้าจะทำต้องแยกเป็นโปรเจกต์ EA ต่างหากตามที่สเปกวางไว้ (และต้องมี exposure cap เพราะนี่คือ
   ต้นเหตุ DD หนักของบอทเดิม: 19/6 เติม short 3 ชั้นระหว่างราคาไหลสวน margin level ลงไปแตะ 199)
4. ยอมรับว่าเป้าจริงควรเป็น **PF 1.2–1.5 ที่ DD ต่ำ** ไม่ใช่ MAR 3.1
